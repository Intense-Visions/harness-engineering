Fix roadmap auto-done failing to land its flip on a branch-protected `main`. The `roadmap-auto-done` workflow pushed the shard flip directly to the base branch; when a repository rule requires PRs ("changes must be made through a pull request") that push is rejected (`GH013`) and the flip is lost — the merged issue's row stays `planned`. The commit step now: (1) disables husky so a hook can't dirty the tree and wedge the rebase ("cannot pull with rebase: unstaged changes"), (2) hard-resets to its own commit before each direct-push retry, and (3) falls back to a self-approved, auto-merged PR when the direct push is blocked — mirroring the baseline-refresh job. The self-approval is scope-guarded (`scripts/assert-diff-scope.mjs`, generalized from the #531 baseline guard to support directory prefixes) so `BASELINE_AUTOAPPROVE_PAT` can only approve PRs confined to `docs/roadmap.md` + `docs/roadmap.d/`. CI/scripts only; no package API change, no release intended.
