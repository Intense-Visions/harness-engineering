feat: the review provenance stamp in `harness pre-merge-brief` (shift-left pipeline fidelity, unit 4 of 5).

`harness pre-merge-brief` gains a **Review provenance** section between the review verdict and the Signal status. It reads the stamp `harness review-provenance render` printed into the PR body and shows it as stated in the PR body, not verified: the section always opens by saying so, because the PR author writes the body and the receipts it would be checked against are machine-local. It keeps only rows and notes the renderer can write and counts the lines it left out; it shows a body the reader did not read as `conflicting`, `too-large` or `ambiguous` (with its reason), never as "no pipeline review recorded" and never as a pass; it prints "unavailable" when the PR body could not be read; it shows a stamp it found but could read no line of as its own state; and it says whether the stamp covers the PR head, comparing it with the head the `final-all` row reviewed whatever that row's Gate cell says, so an overridden final review at an older commit reads as not covering later commits. A `gh` reply that is not a pull request reads as unavailable, never as "no PR". `--pr <number>` names the PR to read and comment on (default: the number in `GITHUB_REF`, else the current branch's PR) and takes only a positive decimal number within the safe integers: anything else, or a malformed `refs/pull/` ref, exits 1 and nothing is read or posted. The review verdict's finding lists show 50 items and then `+N more`; a brief still longer than 60,000 characters is cut section by section at line ends, never in the Review provenance section and in "Worth your eyes" only last, with a mark naming the sections that lost text. The required-review workflow and the `ci-pre-merge-brief` template pass `--pr` and re-run on `edited`, so a body edit refreshes the brief.

Core adds `renderParsedStamp` and `stampCoverage` next to `parseProvenanceStamp`, and `ParsedProvenanceStamp.noReview`; the CLI adds the PR reader (`defaultPrReader`, `resolvePrNumber`) in `github/pr`, which reads the PR's body, head and comments in one `gh pr view` that the poster reuses.
