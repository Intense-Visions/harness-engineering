feat: review receipts, a credential-free receipt gate and risk-tiered reviews (shift-left pipeline fidelity, unit 1 of 5).

- **Receipts.** Every review writes a typed `receipt.json` and one findings file per reviewer under `.harness/sessions/<slug>/reviews/<moment>-<phase>/` (standalone: `.harness/reviews/<branch>-<head sha>/`). A phase review's directory is `phase-N`, where `N` is the phase's 0-based position. A findings file carries the commit its reviewer read (`head`), and every blocking finding in it carries `findingClass` and `escapedFrom` (`ReviewFinding` gains both as optional fields). Contract types, including the gate's failure codes as a literal union, are exported from `@harness-engineering/types`; validators and the gate from `@harness-engineering/core`.
- **Gate.** New `harness check-review-receipt [path] [--moment phase|final|standalone]` and `check_review_receipt` MCP tool. They recompute HEAD, the diff's file set, the base's ancestry and a final review's merge base, read each findings file, treat the receipt's fields as claims, and fail (exit 1) on a missing receipt, a moment that is not the one the review directory states, a required reviewer that did not run, a reviewer id that is not a known reviewer, a light roster that is not the single reviewer `compliance-bug`, a findings file that is absent, invalid, shared, written at another head or outside the diff, a finding id used twice, `blocking` or `advisory` counts that differ from what the findings files hold (one per finding), a head that is not the current HEAD, a base that is not an ancestor of the head, and a final review that is not full, cold and based at the merge base. The review directory decides the moment: `--moment` is read only for a directory that states none, and a flag that contradicts the directory fails. `baseSource: "starting-commit"` is accepted only when no default-branch merge base resolves and the base is the session's starting commit (an unknown starting commit fails `STARTING_COMMIT_UNKNOWN`); the merge base comes from the clone's local remote-tracking refs, so it is only as trustworthy as they are. One more mode: `--findings <file> --base <sha> --head <sha>` is a reviewer's self-check of its own findings file with the gate's parser. A receipt or findings file is read only when it is a regular file of at most 5 MB, and the MCP tool confines the receipt path to the project by real path. No model credential is needed. The gate does not prove that reviewers ran in separate contexts, and it does not recompute the conditional-reviewer set (only that every id is known), a phase's entitlement to the light tier, or what a reviewer says it read.
- **Tiers.** New `harness review-tier` command over the new core export `selectReviewTier`: a phase review is `full` on a risk keyword (in the diff, a changed path or a commit message of the range), a package entry point, high complexity or thorough rigor, and `light` otherwise. The diff is read as text whatever git attributes say, and of the trailers git identifies in a message only identity trailers are left out of the match (the rule is `IDENTITY_TRAILER` in core's `tier-selector.ts`; the `harness-code-review` skill states it). A diff too large for git's output buffer is `full` (`diff-too-large`). The final review is always `full`, and for a final or standalone review the command prints the base the receipt gate will demand (`--session` supplies the starting commit). The command runs git from the repository top level, gathers the diff itself, reads `review.backend` from the repository top's `harness.config.json` and prints the tier, its reasons and the resolved backend (`--pipeline-runner` says the session can run the coded pipeline; without it a configured pipeline is reported as degraded to `agent`; a `light` review is always `agent`). Autopilot now dispatches one reviewer per record instead of handing the whole review to one subagent, and a session that cannot dispatch records `tier: light`.
- **Cold final review.** Autopilot's final review covers the diff from the merge base and gives reviewers no prior findings. A commit after it returns to the final review. A failed mechanical phase is a red check (fix or stop), never a gate override.
- **Config.** New optional `review.backend`: `"agent"` (default) or `"pipeline"`, read from the repository top's `harness.config.json`.
