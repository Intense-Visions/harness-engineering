## Summary

The `packages/cli/tests/agent-definitions` module validates the persona-to-agent-definition pipeline across four platforms (Claude Code, Codex, Cursor, Gemini CLI). It tests persona→definition generation using task-aware description lookups and skill concatenation, then verifies platform-specific rendering (YAML frontmatter for markdown formats, TOML escaping for Codex, field presence rules). The generator pulls skill contents and applies platform-aware transformations; renderers format output for each platform's schema while preserving role, steps, and methodology sections.

## Invariants

- GEMINI_TOOL_MAP must have an entry for every tool in DEFAULT_TOOLS
- AGENT_DESCRIPTIONS provides task-aware descriptions for known persona types; falls back to persona description if absent
- All renderers must include 'Generated by harness generate-agent-definitions' header for orphan detection
- Claude Code and Cursor outputs start with YAML frontmatter (---), include name and description fields
- Codex uses TOML format with triple-quoted literal strings ('''…''') for shell snippets to preserve backslashes; falls back to triple-double-quotes if body contains '''
- Codex description field must be single-line in output, even when input is multi-line
- Methodology section only renders when non-empty
- Multi-skill concatenation separates skills with --- delimiter
- Steps format consistently as 'N. [command/skill name] (trigger)' across all platforms
- Codex omits tools field; Claude Code includes it; Cursor/Gemini follow their platform conventions
- Unknown step types handled gracefully with fallback text (e.g., 'Unknown step')
