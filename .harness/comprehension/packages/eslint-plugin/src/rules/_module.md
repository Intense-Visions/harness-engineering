## Summary

The `packages/eslint-plugin/src/rules` module defines 21 ESLint rules enforcing code quality, architectural boundaries, and testing practices. Rules span documentation (enforce-doc-exports), architecture (no-circular-deps, no-layer-violation), and testing (no-disabled-tests, no-focused-tests). Each rule implements ESLint's RuleModule contract with metadata, options schema, and AST visitor callbacks. The module exports a single barrel `rules: Record<string, RuleModule<...>>` mapping rule names to implementations.

## Invariants

- Auto-generated barrel is source of truth: index.ts is generated by scripts/generate-rules-barrel.mjs; manual edits are lost. Adding a rule requires running `pnpm generate:rules` to regenerate.
- Type annotation protects downstream builds: rules export uses explicit Record<string, TSESLint.RuleModule<string, unknown[]>> typing to resolve @typescript-eslint/utils types directly (not hoisted .pnpm paths), preventing TS2742 errors in consumers.
- Import graph persists across lint run: no-circular-deps maintains module-level importGraph Map accumulating edges across all files in a single lint invocation, enabling cycle detection without re-analysis. Graph clears only via exported clearImportGraph() for testing.
- Context is the only runtime bridge: each rule's create function receives ESLint context as sole authority for sourceCode, filename, and configuration. All reporting flows through context.report().
- Schema validation gates option passing: ESLint validates user rule options against meta.schema before passing to create(). Rules must declare complete schemas for all accepted option shapes or risk configuration errors.
