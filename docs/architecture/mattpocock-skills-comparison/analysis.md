# Analysis: mattpocock/skills vs Harness Engineering

**Date:** 2026-10-13
**Skill:** harness-architecture-advisor (Phase 2 ANALYZE, read-only, facts only)
**Source snapshot:** mattpocock/skills @ `49dd158d` (2026-10-09), v1.3.1, MIT, ~289k stars. Read-only shallow clone; nothing executed.
**Prior art:** `docs/ideation/external-source-feature-matrix-2026-08-10.md` compared the two at the _feature_ level. This document compares at the _technique_ level (how skills are written, loaded, composed, governed) and does not re-litigate that matrix.

## 1. Shape of the two systems

| Dimension            | mattpocock/skills                                                                 | Harness                                                                                                        |
| -------------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Skill count          | 38 total, 27 shipped                                                              | 793 dirs in `agents/skills/claude-code/` (17 tier-1, 73 tier-2, 697 tier-3), x4 platform mirrors               |
| Total SKILL.md lines | 2,686 (all 38)                                                                    | 148,208 (claude-code tree); 26,908 for tier-1+2 alone                                                          |
| Median SKILL.md      | well under 100; max 170 (`pr`)                                                    | 173 overall; **239 for tier-1+2**; p90 530; max 1,149                                                          |
| Runtime              | None. Pure markdown + 4 templates                                                 | MCP server (~62 tools), CLI, graph, orchestrator, hooks, state                                                 |
| Enforcement          | None mechanical; prose only                                                       | ESLint rules, validators, baselines, hooks, CI gates                                                           |
| Skill evals          | None ("There is no automated eval", `docs/productivity/writing-for-agents.md:47`) | None for skill _behavior_; adoption telemetry + `harness-catalog-retrospective` measure _usage_ only           |
| Versioning           | Whole set, Changesets                                                             | Per-skill `version` in `skill.yaml`; package releases via Changesets                                           |
| Distribution         | Official Anthropic marketplace + own marketplace (Codex/Copilot) + skills.sh      | Own plugins per host (`.claude-plugin/`, `.codex-plugin/`, `.cursor-plugin/`, `.antigravity-extension/`) + npm |

The systems sit at different layers. Harness is a constraint substrate with skills on top; mattpocock/skills is _only_ the skill layer, and it states its philosophy against process-owning frameworks: "Approaches like GSD, BMAD, and Spec-Kit try to help by owning the process... take away your control" (`README.md`). Harness is, by that definition, a process-owning framework.

## 2. Always-loaded context cost (per turn, every session)

| Measure                                             | mattpocock/skills                                  | Harness                                                                               |
| --------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Model-invocable entries                             | 11 (16 of 27 set `disable-model-invocation: true`) | 89 slash commands in `.claude-plugin/commands/`, **0** use `disable-model-invocation` |
| Description chars, always loaded                    | 2,299 total                                        | 25,800 total (median 214, max 1,475)                                                  |
| Descriptions using trigger phrasing ("Use when...") | All model-invoked ones (`.agents/invocation.md`)   | **0 of 89** (`grep '^description:.*[Uu]se when'`)                                     |

Evidence: command frontmatter in `.claude-plugin/commands/*.md` (generated by `packages/cli/src/slash-commands/render-claude-code.ts`); e.g. `acceptance-eval.md` description is 600+ chars of capability summary ("Authority is derived in TypeScript, never from the LLM...") rather than when-to-reach phrasing.

Tier-3 skills: `.claude-plugin/plugin.json` declares `"skills": ["./agents/skills/claude-code"]`, but **no harness SKILL.md has YAML frontmatter** (0 of 793 begin with `---`). Session evidence: in this session's skill listing, no tier-3 skill (e.g. `a11y-*`, `angular-*`) is surfaced; only the 89 `harness:*` commands are. [UNVERIFIED] whether Claude Code silently ignores frontmatter-less SKILL.md files or loads them with no description; either way they contribute no discoverable trigger, and discovery relies on the `search_skills` MCP tool.

mattpocock's governing rule (`writing-for-agents/SKILL-MECHANICS.md`): "Pick model-invocation only when the agent must reach the skill on its own, or another skill must. If it only ever fires by hand, make it user-invoked and pay no context load."

## 3. Skill-body authoring discipline

| Measure                                                   | mattpocock/skills                                                                                                                                                              | Harness (tier-1+2)                                                                                                                                                                                                                                |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Negation density (lines with NOT/Never/STOP/Do not/Don't) | 52 / 1,854 = **2.8%**                                                                                                                                                          | 1,792 / 26,908 = **6.7%** (2.4x)                                                                                                                                                                                                                  |
| Explicit authoring principle on negation                  | "steering by prohibition drags the forbidden behaviour into context and makes it _more_ available... Prompt the **positive**" (`writing-for-agents/SKILL.md`)                  | None found. Harness _mandates_ negative framing: `## Red Flags`, "If you catch yourself... STOP", `Rationalizations to Reject` (`agents/skills/templates/discipline-template.md`, ADR in `docs/architecture/agent-skills-comparative/ADR-001.md`) |
| Progressive disclosure                                    | Sibling reference files loaded on demand in most substantive skills (`tdd/tests.md`, `codebase-design/DEEPENING.md`, `prototype/LOGIC.md` vs `UI.md`, `triage/AGENT-BRIEF.md`) | 5 of 793 skills have a `references/` dir; 1 has `scripts/`                                                                                                                                                                                        |
| Pruning discipline                                        | Named concept "sediment"; prune no-ops, duplicated sources, environment-derivable content (`writing-for-agents/SKILL.md`)                                                      | Skill validator is **additive only**: `packages/cli/src/commands/skill/validate.ts:35-56` requires h1 + `BEHAVIORAL_REQUIRED_SECTIONS` + `RIGID_SECTIONS`; no size, density, or no-op check                                                       |
| "Leading words" / concept anchors                         | Deliberate short terms (frontier, seam, tracer bullet, fog of war, deep module)                                                                                                | Cognitive modes, EXISTS/SUBSTANTIVE/WIRED, tiers — present but not a stated authoring technique                                                                                                                                                   |

Observation: harness's authoring rules accrete required sections into every skill; mattpocock's authoring rules subtract. The 2026-04 agent-skills ADR made `Common Rationalizations` mandatory — the opposite direction from mattpocock's negation principle. Neither side has measured which direction produces better agent behavior.

## 6. Governance of the catalog

| Mechanism                     | mattpocock/skills                                                                                                                    | Harness                                                                                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admission rule for new skills | `SCOPE.md`: needs an observed failure in a real session; "If the behaviour composes from existing skills, it does not get a new one" | `emit_skill_proposal` + soundness gate (structural checks only, `packages/orchestrator/src/proposals/gate.ts`); no composition or observed-failure test |
| Rejected-idea memory          | `.out-of-scope/*.md` (9 records, each with rationale + prior requests); `triage` checks them before re-opening                       | None. Rejections live in ideation docs prose (e.g. feature matrix "Out of scope" rows) and closed issues                                                |
| Retirement                    | "a retired skill is deleted" (`skills/deprecated/README.md`)                                                                         | `catalog-retrospective` flags quiet skills; no deletion rule                                                                                            |
| Bucket lifecycle              | `in-progress/` (beta, not shipped) → `engineering/`/`productivity/` (promoted) → `misc/` (frozen)                                    | `stability` field in skill.yaml; tiers govern loading, not maturity                                                                                     |

## 7. Where harness is categorically stronger (no adoption question)

Mechanical enforcement, state, verification depth, knowledge graph, orchestration/fleets, multi-persona review, blast radius, telemetry, rollback, roadmap sync. mattpocock/skills has none of these by design ("small, easy to adapt, and composable"). These were already judged harness-better in the 2026-08-10 matrix; this pass confirms that and does not revisit them.

## 8. Facts relevant to the decision

1. Harness's always-loaded description cost is ~11x mattpocock's (25.8k vs 2.3k chars), with none of it written as trigger phrasing.
2. Harness's tier-1/2 bodies are ~3-5x longer and 2.4x more negation-dense; the harness skill validator mechanically _requires_ accretion and checks nothing about size or density.
3. Neither side measures skill _behavior_ (does the right skill fire; does following it produce the right outcome). Harness measures adoption; mattpocock measures nothing.
4. Harness has no rejected-idea record, which is directly relevant to this very session: discovery found a prior pass on the same repo that the human did not remember.
5. Five discrete per-skill techniques (repro-command gate, seams, vertical slices, project glossary, deep-module vocabulary) have no harness counterpart; one (frontier interviews) is already filed.
