# AMR Phase 5 — Orchestrator Routing Endpoints (closes the Shuttle mutual-deferral seam)

**Status:** Draft · **Tier:** Medium-Large · **Domain:** orchestrator (server + agent)
**Keywords:** routing-policy-ingestion, routing-telemetry, RoutingCapableAdapter, wire-contract, allowedProviders, default-off

## Overview

A cross-PR review of AMR (#796), split-routing (#800), and Shuttle tenant-routing ([tangentleap/shuttle#131](https://github.com/tangentleap/shuttle/pull/131)) found a **mutual-deferral seam**: Shuttle ships a fully-built control plane that pushes per-tenant `RoutingPolicy` to the orchestrator and drains routing telemetry back — but it talks only to a **mock orchestrator**. The real harness orchestrator has neither endpoint, no runtime policy-ingestion path, and a `RoutingDecision` shape that does not match Shuttle's telemetry wire type. AMR deferred these "to Shuttle"; Shuttle deferred them back "to harness" — so no harness work owns them.

This spec closes that seam on the harness side: the two D6 HTTP endpoints, runtime policy ingestion (hot-swapping `AdaptiveRouter`), a telemetry projection matching Shuttle's wire shape, and the `allowedProviders` allowlist AMR left dormant.

**Wire contract authority:** Shuttle `src/types/routing.ts` — `RoutingPolicy` (in), `RoutingTelemetry = { decisions: RoutingDecision[], spentUsd }` where Shuttle's `RoutingDecision = { decisionTs, tierRequired, backend, estCostUsd, workItemId?, domainId? }` (out). Endpoints MUST match this exactly (verified against that file).

## Why now

1. **Three otherwise-coherent PRs don't integrate end-to-end** without these endpoints — Shuttle's push has nowhere to land and its telemetry drain reads nothing (against a real orchestrator).
2. **The `RoutingDecision` mismatch is a latent zero-rows bug** (cross-PR review C1): harness's internal `RoutingDecision` (`{timestamp, backendName, backendType, resolutionPath, …}`) cannot serialize to Shuttle's telemetry shape. Only a harness-side projection fixes it.
3. **`allowedProviders` is coordinated but half-built** — AMR shipped `RoutingPolicy` without it (comment: "Phase 5") and left `selectCheapestQualifying`'s allowlist branch dormant; Shuttle already sends it.

## Non-goals

- **Multi-tenant fan-out inside one orchestrator.** AMR is one-orchestrator-container-per-tenant (AMR proposal §Assumptions); "per-tenant" = container isolation. These endpoints set _this container's_ policy — no tenant keying inside the process.
- **Changing routing/dispatch behavior when off.** Default-off holds: no policy pushed → `adaptiveRouter` stays `null` → byte-identical dispatch.
- **The 4c quality-gate fan-in** — separate follow-up (4b's workflow engine already feeds a per-stage outcome; richer gate-verdict fan-in is out of scope here).
- **Auth/mTLS on the endpoints** — assumed handled by the existing orchestrator HTTP server's auth layer (same as `/config`,`/decisions`,`/trace`); this spec adds routes, not a new auth model.

## Technical Design

- **Types (`packages/types/src/orchestrator.ts`):** add `allowedProviders?: BackendDef['type'][]` to `RoutingPolicy`; add `RoutingTelemetryDecision` + `RoutingTelemetry`. **Barrel is hand-maintained** (`packages/types/src/index.ts` — curated `export type` block, not generated); add the two new type names there. `@harness-engineering/core` re-exports via `export *`, so no core-barrel edit is needed (the curated-allowlist gotcha applies only to new core-native modules).
- **`AdaptiveRouter` (`agent/adaptive-router.ts`):** `setPolicy(policy)` — swap the policy + re-derive the policy-dependent state (registry / `providerOf` / allowlist / escalation-threshold-derived config) while **keeping the existing `EscalationState` instance** (its `deps` is currently `private readonly` — `setPolicy` restructures the policy-derived slice to be mutable, keeping `escalation` by reference). Populate `buildConstraints`'s currently-dormant `allowed` from `policy.allowedProviders`. A `drainTelemetry(): RoutingTelemetry` that reads `this.deps.decisionBus`, **filters to enriched rows** (`estCostUsd !== undefined`), and projects (D2).
- **Orchestrator (`orchestrator.ts`):** an `ingestRoutingPolicy(policy)` method — if empty → `this.adaptiveRouter = null`; else if `adaptiveRouter` exists → `setPolicy`; else construct it (the `:703` path) with the pushed policy. Exposed to the server layer.
- **Server deps plumbing (feasibility review):** `RoutingRouteDeps` currently carries only config **snapshots** (`router`/`bus`/`routing`/`backends`), not the live orchestrator. Thread a live accessor through `ServerDependencies` → `RoutingRouteDeps` — an `ingestRoutingPolicy(policy)` fn and a `drainRoutingTelemetry()` fn (bound to the orchestrator instance) — so the handlers can mutate `adaptiveRouter` and read the live router. This is real wiring, not a pure handler add.
- **Server (`server/routes/v1/routing.ts` + `http.ts` + `v1-bridge-routes.ts`):** `PUT /policy` (`admin` scope) → Zod-validate → `ingestRoutingPolicy` → 204; `GET /telemetry` (`read-telemetry` scope) → `drainRoutingTelemetry()` → JSON. Register both in `V1_BRIDGE_ROUTES`.

## Integration Points

- **Entry Points:** two new v1 routes; `AdaptiveRouter.setPolicy`/`drainTelemetry`; `orchestrator.ingestRoutingPolicy`.
- **Registrations:** barrel regen for the new types; route registration in the v1 dispatcher.
- **Documentation Updates:** AMR proposal "Deferred follow-ups" → these endpoints LANDED; AGENTS.md staged-dispatch wording (D6); the cross-repo wire contract documented.
- **Architectural Decisions:** D1 (mutate-not-reconstruct, preserve escalation/budget), D2 (telemetry projection) warrant ADRs.
- **Knowledge Impact:** "runtime routing-policy ingestion", "routing telemetry projection" enter the graph.

## Success Criteria

- **SC1** — `PUT /routing/policy` with a valid `RoutingPolicy` ingests it and the NEXT dispatch routes under the new policy (hot-swap); the `EscalationState` climbed floor from before the update is **preserved** (not reset). _(Spend preservation is out of scope — no live spend accumulator exists today; see D1.)_
- **SC2** — `PUT` with an empty `{}` policy sets `adaptiveRouter = null` → default-off restored (byte-identical dispatch); absent any PUT, behavior is unchanged.
- **SC3** — `GET /routing/telemetry` returns `{ decisions, spentUsd }` where each decision matches Shuttle's wire shape (`decisionTs`/`tierRequired`/`backend`/`estCostUsd`/`workItemId?`/`domainId?`) and `spentUsd` is the sum — **a real drain against Shuttle's `RoutingDecisionSchema` deserializes to non-empty rows** (an integration test asserts the projection satisfies Shuttle's mock-orchestrator contract shape). The projection includes **only enriched decisions** (base `BackendRouter` emits without `estCostUsd` are excluded), so row count and `spentUsd` are not inflated by the dual-emit.
- **SC4** — a policy with `allowedProviders` excludes non-allowed backends from tier selection (the allowlist is live); a policy without it is unaffected.
- **SC5** — `PUT` returns 204 (no body); the existing `/config`,`/decisions`,`/trace` routes + `BackendRouter`/`AdaptiveRouter` behavior are unchanged.

## Implementation Order

**Phase 1 — Types + `setPolicy`/allowlist + `drainTelemetry` (~3d).** `allowedProviders` + telemetry projection types; `AdaptiveRouter.setPolicy` (preserving escalation/budget), the `allowedProviders`→`allowed` wiring, and `drainTelemetry()` projection. Prove SC1(router-level hot-swap)/SC4/the projection shape (SC3 unit).

**Phase 2 — Endpoints + ingestion (~3d).** `orchestrator.ingestRoutingPolicy` (null/setPolicy/construct); `PUT /policy` (→204) + `GET /telemetry` routes; default-off boundary. Prove SC1(end-to-end)/SC2/SC5 + an integration test that the telemetry payload satisfies Shuttle's wire shape (SC3).

**Phase 3 — Docs + wire-contract note (~1d).** D6 doc fixes; document the cross-repo contract; flip the AMR/Shuttle deferred-lists to LANDED.

**Total:** ~7 working days. Branched off #796 (sibling to #800); depends only on AMR. When #796 merges, rebases to main; Shuttle #131 then has a real server to talk to.
