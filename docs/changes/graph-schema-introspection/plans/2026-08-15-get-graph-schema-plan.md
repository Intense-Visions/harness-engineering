# Plan: get_graph_schema — read-only graph schema introspection MCP tool

**Date:** 2026-08-15 | **Spec:** docs/changes/graph-schema-introspection/proposal.md | **Tasks:** 5 | **Time:** ~35 min | **Integration Tier:** low

## Goal

Add a read-only MCP tool `get_graph_schema` that enumerates the knowledge graph's
shape (node-type counts + property keys, edge-type counts, relationship patterns)
from the already-persisted graph, register it in the served MCP tool registry, and
prove via tests over a seeded graph that the reported counts/patterns/properties
are correct — so an agent can discover the schema before querying.

## Observable Truths (Acceptance Criteria)

Mirrors proposal.md §Observable Truths (1–6). In short: tool defined + registered +
capability-declared; stable JSON shape `{ nodeTypes, edgeTypes, patterns, totals }`;
exact counts over a seeded graph; deterministic sorted property union per label;
read-only guard behavior; documented + link-referenced.

## Tasks

1. **[TDD]** Write `get-graph-schema.test.ts` first: guard paths (reuse the
   query-graph.test.ts pattern) + a seeded-graph test that builds a `GraphStore`,
   `save`s it to the resolved graph dir, then calls `handleGetGraphSchema` and
   asserts exact node/edge counts, a known pattern triple, and the sorted property
   union for one label. Red (module missing).
2. **[IMPL]** Implement `get-graph-schema.ts`: load store via `loadGraphStore`,
   guard with `graphNotFoundError`, aggregate `findNodes({})` + `getEdges({})` into
   the `{ nodeTypes, edgeTypes, patterns, totals }` shape with deterministic
   sorting; return the text envelope. Green.
3. **[WIRE]** Export from `index.ts`; import + register in `server.ts` (definitions
   array + `TOOL_HANDLERS`); add capability declaration. Add a registry test
   assertion (or extend an existing one) that `get_graph_schema` is served.
4. **[DOCS+CHANGESET]** Run `pnpm run generate-docs`; add the changeset (minor,
   cli). Ensure a `docs/` page link-references the new source file for coverage.
5. **[VALIDATE]** Build graph+cli, typecheck, run new tests + registry/tool tests,
   lint, prettier. Confirm the tool appears in the served list.

## Constraints & Risks

- **[CONSTRAINT]** Read-only: never call `store.save` or write; only `findNodes`/
  `getEdges`. Verified by the no-write guard test + code review.
- **[CONSTRAINT — repo policy]** Shipped surfaces (tool description, docs) carry no
  internal roadmap/PR identifiers; only proposal + changeset may reference #1280.
- **[RISK]** Registration is the classic silent no-op — a defined-but-unregistered
  tool. Mitigation: Task 3 adds a registry-list assertion; Task 5 confirms the
  served list.
- **[RISK]** Property union nondeterminism. Mitigation: sort keys before emit;
  test asserts exact array.
- **[RISK]** Node-24 better-sqlite3 ABI break in tests. Mitigation: run under
  Node 22 (per fleet setup).
