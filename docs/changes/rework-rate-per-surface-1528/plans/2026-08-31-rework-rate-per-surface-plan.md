# Plan: Instrument rework rate per surface

**Date:** 2026-08-31 | **Issue:** #1528 | **Spec:** `docs/changes/rework-rate-per-surface-1528/proposal.md` | **Tasks:** 9 | **Time:** ~40 min | **Integration Tier:** medium | **Route:** feature (report-only, does not gate)

## Goal

Add a per-surface (file-path) rework-rate metric derived from local git history — reusing the existing `scan-candidates` git-walking machinery — exposed as a new `harness rework` command (human table + `--json`) and surfaced as a `reworkRate` metric block plus `rework-hotspot` signal in the health snapshot, splitting planned (roadmap-linked multi-part delivery) from unplanned (waste) rework, report-only and degrade-safe.

## Observable Truths (Acceptance Criteria)

1. **(AC1)** Given a fixture git history built in a temp repo, a `fix:`/`revert:` commit that re-touches an already-changed surface AND shares an issue ref in the injected planned-issue set is classified `planned`; the same shape with NO planned issue ref is classified `unplanned`. Asserted deterministically by injecting the planned-issue set. — Tasks 2, 3
2. **(AC2)** Both the returned `ReworkReport` object and the `--json` stdout payload declare a `denominatorLabel` (e.g. `"commits touching the surface within the window"`) and the `resolvedWindow` (the normalized lookback). — Tasks 2, 5
3. **(AC3)** A surface whose unplanned rework rate crosses the attention threshold raises the `rework-hotspot` signal and populates the `reworkRate` metric block (`maxUnplannedReworkRate`, `reworkSurfaceCount`) in the health snapshot. — Tasks 6, 7, 8
4. **(degrade-safe)** Non-git directory, empty repo, and an empty-window all yield an empty `ReworkReport` and exit 0 — never a throw, never a gate. — Tasks 2, 5
5. **(single-walker)** Rework reuses `normalizeSince` and a single shared commit reader factored out of `scan-candidates`; `git-scan.ts` is refactored to consume the same reader so no second git walker exists. — Task 1

### Task 1: Factor a shared commit reader out of `scan-candidates` (single-walker guarantee)

**Depends on:** none | **Files:** `packages/core/src/solutions/scan-candidates/read-commits.ts`, `packages/core/src/solutions/scan-candidates/read-commits.test.ts`, `git-scan.ts`, `index.ts` | **Owns:** `packages/core/src/solutions/scan-candidates/**`

**Tests first** (`read-commits.test.ts`, temp-git fixture built with `execFileSync('git', …)` in a `mkdtemp` dir — mirror the existing `git-scan.test.ts` fixture style):

1. `readRawCommits` returns commits oldest→newest? (Decide + assert order explicitly; the rework model requires a documented order. Reverse `git log` default newest→oldest to oldest→newest inside the reader.) Assert `sha`, `subject`, `body`, `files[]` for a 2-commit fixture where one commit body contains `Closes #123`.
2. Body with embedded newlines does NOT leak into `files` (fixture commit with a multi-line body) — proves the field-separator parse is robust.
3. Empty repo (`git init`, no commits) → `[]`, no throw (assert `EMPTY_REPO_RE` path).
4. Non-git dir → `[]`, no throw.

**Implementation:**

- Create `read-commits.ts`: move `RawCommit` (extend to `{ sha; subject; body; files }`), `EMPTY_REPO_RE`, and the reader logic here as `export async function readRawCommits(opts: { since: string; cwd: string }): Promise<RawCommit[]>`. Use `git log --since=… --name-only --format=%x1e%H%x1f%s%x1f%b%x1f` (add `%b` body field + trailing `%x1f`); split records on `\x1e`, split each record on `\x1f` into `[sha, subject, body, filesBlob]`, and derive `files` from `filesBlob.split('\n')` filtered non-empty. This isolates multi-line body from the file list. Reverse to oldest→newest.
- Refactor `git-scan.ts`: delete the private `readCommits` + `RawCommit` + `EMPTY_REPO_RE`; import `readRawCommits` and map to `ScannedCommit` (ignore `body`). Keep `normalizeSince` and `FIX_RE` where they are. The existing `git-scan.test.ts` is the regression guard — it must still pass unchanged.
- Export from `index.ts`: `export { readRawCommits } from './read-commits';` and `export type { RawCommit } from './read-commits';`.

### Task 3: Implement `computeRework` + classification (AC1)

**Depends on:** Task 1, Task 2 | **Files:** `packages/core/src/rework/rework.ts`, `packages/core/src/rework/rework.test.ts` | **Owns:** `packages/core/src/rework/**`

**Tests first** (`rework.test.ts`, temp-git fixture helper like Task 1):

1. **AC1 planned:** history = [commit A touches `src/foo.ts` `feat: add foo (#42)`] then [commit B touches `src/foo.ts` `fix: correct foo` body `Refs #42`], planned-issue set `{42}` injected → `src/foo.ts` surface has `plannedReworkCommits: 1`, `unplannedReworkCommits: 0`, `unplannedReworkRate: 0`.
2. **AC1 unplanned:** same shape but commit B refs `#99` (not in `{42}`) → `unplannedReworkCommits: 1`, `unplannedReworkRate: 1/2 = 0.5`, `reworkingShas` contains B.
3. **Not rework — no earlier touch:** a lone `fix:` commit touching a surface no earlier commit touched → 0 rework (rule 3b: needs a strictly-earlier commit on the same surface).
4. **Not rework — not a fix subject:** a non-`fix`/`revert` commit re-touching a surface → 0 rework (rule 3a).
5. **`revert:` and `Revert "…"`** subjects both count as rework commits.
6. **`minCommits` filter:** surface with fewer than `minCommits` total commits is excluded.
7. **denominator = commits touching THAT surface** (not global): fixture with two surfaces of different commit counts asserts per-surface denominators.
8. **degrade-safe:** empty repo / non-git → `surfaces: []`, `totalCommitsScanned: 0`, no throw.

**Implementation:**

- `plannedIssuesFromExternalIds(externalIds: string[]): Set<number>` — map each via `parseExternalId`, collect `.number`.
- `classifyRework(subject: string, body: string, planned: Set<number>): ReworkClassification` — `parseReferencedIssues(`${subject}\n${body}`)`; `planned` if any parsed ref ∈ `planned`, else `unplanned`.
- `computeRework(opts): Promise<ReworkReport>` — call `readRawCommits({ since, cwd })` (oldest→newest); build `Map<surface, commits[]>`; a `REWORK_SUBJECT_RE` (`/^(fix(\([^)]+\))?:|revert:|Revert ")/i`) marks candidate; a candidate is rework for a surface only if a strictly-earlier commit in the list already touched it; classify each rework commit; aggregate per surface; apply `minCommits` (default 2); compute `unplannedReworkRate = unplannedReworkCommits / totalCommits`; sort surfaces by `unplannedReworkRate` desc; set `resolvedWindow = normalizeSince(since)`, `denominatorLabel = 'commits touching the surface within the window'`, `generatedAt = (opts.now?.() ?? new Date()).toISOString()`. Wrap the read in try/catch → empty report on any git failure (degrade-safe).

Run: `npx vitest run packages/core/src/rework/rework.test.ts`

## Uncertainties

- **[ASSUMPTION]** Commit order for the rework rule is oldest→newest; `git log` defaults to newest→oldest, so the shared reader reverses. If a fixture proves otherwise, only Task 1's ordering line changes.
- **[ASSUMPTION]** `REWORK_ATTENTION_THRESHOLD = 0.2` (20% unplanned rework) is the initial signal threshold — a tunable constant, not load-bearing for correctness. Adjustable without structural change.
- **[ASSUMPTION]** Planned-issue set in the CLI derives from roadmap shard `External-ID`s best-effort; when no roadmap exists the set is empty and all rework counts as unplanned (documented, degrade-safe). The core module stays roadmap-agnostic via the injected `plannedIssues` set (keeps AC1 deterministic and core free of a cli/roadmap dependency direction violation).
- **[DEFERRABLE]** PR-fanout / superseded-PR enrichment via GitHub API is explicitly out of scope (spec Non-Goals) — recorded as remainder.
