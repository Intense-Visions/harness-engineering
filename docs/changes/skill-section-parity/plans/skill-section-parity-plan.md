# Plan: Skill required-section parity — one source of truth for the two gates

**Date:** 2026-08-07 | **Spec:** `docs/changes/skill-section-parity/proposal.md` | **Tasks:** 15 | **Time:** ~58 min | **Integration Tier:** medium

## Goal

Make the `harness skill validate` CLI validator and the `agents/skills` vitest structure test derive their required-section lists from a single exported constant in `@harness-engineering/core`, then author a domain-specific `## Rationalizations to Reject` section in each of the 19 claude-code skills the newly-strengthened gate now flags — so gate drift is structurally impossible and every shipped behavioral skill carries the section it was always supposed to.

## Observable Truths (Acceptance Criteria)

Mapped to the spec's 5 success criteria (SC#):

1. **(SC1)** `packages/core/src/skills/required-sections.ts` exports `BEHAVIORAL_REQUIRED_SECTIONS` (6 entries incl. `'## Rationalizations to Reject'`), `KNOWLEDGE_REQUIRED_SECTIONS`, and `RIGID_SECTIONS`, each `as const`; `packages/core/src/index.ts` re-exports the `skills` module. Both `validate.ts` and `structure.test.ts` import these from `@harness-engineering/core`, and grep for the inline literal array `'## When to Use'` / `'## Rationalizations to Reject'` outside `packages/core/src/skills/` returns nothing.
2. **(SC2)** Reverting any single one of the 19 authored sections makes `agents/skills` vitest go RED on the corresponding `has required sections for its skill type` case citing the missing `## Rationalizations to Reject`. Observable at the Phase 1/Phase 2 boundary: immediately after rewiring `structure.test.ts` (Task 5, before any authoring), `npx vitest run` in `agents/skills` fails on exactly 19 skills for that section.
3. **(SC3)** All 19 skills contain a `## Rationalizations to Reject` section with domain-specific content: no two sections share an identical rationalization row, and none contain internal roadmap/PR/issue numbers (e.g. `#1234`, `PR #`, roadmap IDs).
4. **(SC4)** `harness skill validate` reports 0 errors and `agents/skills` vitest passes fully green.
5. **(SC5)** `npx turbo run build`, `pnpm generate:plugin:check` (EXIT=0), `pnpm run generate-docs` (only the 19 sections appear in the generated-docs diff), `pnpm format:check`, and `harness validate` (modulo pre-existing unrelated roadmap failures) all pass.

The spec only mandates that `validate.ts` and `structure.test.ts` import the constants that exist as arrays. Task 4 replaces the two `validate.ts` inline literals with references to the shared `RIGID_SECTIONS` for full parity; if that expands the diff undesirably, the minimal path is to import only `BEHAVIORAL_REQUIRED_SECTIONS`/`KNOWLEDGE_REQUIRED_SECTIONS` and leave the rigid literals. - [ASSUMPTION] `pnpm run generate-docs` regenerates a skills catalog/reference that embeds skill-body section lists; its only diff will be the 19 new sections. If it produces unrelated churn, Task 14 flags it for human review rather than committing blind.
- [DEFERRABLE] Exact prose of each authored section is fixed during Phase 2; wording can be tuned later without changing the drift contract.

### Task 1: Create the shared core module

**Depends on:** none | **Files:** `packages/core/src/skills/required-sections.ts`, `packages/core/src/skills/index.ts`

1. Create `packages/core/src/skills/required-sections.ts`:

   ```ts
   /**
    * Canonical required-Markdown-section lists for shipped skills.
    *
    * Single source of truth for the two gates that check skill structure:
    * the `harness skill validate` CLI validator and the `agents/skills`
    * vitest structure test both import these. Keeping one definition makes
    * gate drift structurally impossible.
    */

   /** Sections every behavioral (flexible/rigid) skill must contain. */
   export const BEHAVIORAL_REQUIRED_SECTIONS = [
     '## When to Use',
     '## Process',
     '## Harness Integration',
     '## Success Criteria',
     '## Examples',
     '## Rationalizations to Reject',
   ] as const;

   /** Sections every knowledge skill must contain. */
   export const KNOWLEDGE_REQUIRED_SECTIONS = ['## Instructions'] as const;

   /** Additional sections required of rigid skills. */
   export const RIGID_SECTIONS = ['## Gates', '## Escalation'] as const;
   ```

2. Create `packages/core/src/skills/index.ts`:

   ```ts
   export {
     BEHAVIORAL_REQUIRED_SECTIONS,
     KNOWLEDGE_REQUIRED_SECTIONS,
     RIGID_SECTIONS,
   } from './required-sections';
   ```
